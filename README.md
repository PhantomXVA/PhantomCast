# PhantomCast

**Системный звук Windows на Android-телефон по Wi-Fi в реальном времени — задержка ≈ 30–50 мс.**

Телефон как беспроводная колонка или наушники для ПК: игры, видео, музыка, звонки.
Без облака, аккаунтов и драйверов — только ваша локальная сеть.

## Возможности

- 🎧 **Малая задержка** — пакеты по 5 мс, адаптивный джиттер-буфер, `AudioTrack` в low-latency режиме. ≈ 30–50 мс сквозная на Wi-Fi 5 ГГц.
- 🔊 **Без потерь или со сжатием** — PCM 16 бит (1,5 Мбит/с) либо Opus 128 / 192 / 320 кбит/с (режим `lowdelay`).
- 🔎 **Автопоиск** — телефон сам объявляется по mDNS, на ПК остаётся выбрать его и нажать «Старт». Можно ввести IP вручную.
- 🔌 **Автопереподключение** — переживает заминки Wi-Fi и смену устройства вывода.
- 🔋 **Бережёт батарею** — пока ПК не подключён, телефон только слушает порт; звук, WakeLock и WifiLock включаются лишь на время сессии. Экран можно гасить.
- 🎯 **Объёмный 3D-звук для наушников** — 5.1/7.1 превращается в бинауральное стерео (разница времени и громкости между ушами, «тень головы», приглушение заднего звука): в играх слышно, откуда шаги и выстрелы, спереди или сзади. Включается галочкой в окне ПК.
- 📊 **Живая статистика** — оценка задержки, джиттер, потери, срывы на обеих сторонах; индикатор уровня L/R на ПК.
- 🪶 **Лёгкое** — приложение для Android без AndroidX и сторонних библиотек (APK ≈ 0,9 МБ).
- 🛡️ **Не трогает брандмауэр** — ПК делает только исходящие соединения, ничего разрешать в Windows не нужно.

## Быстрый старт

1. **Телефон:** скачайте APK из [Releases](../../releases), установите (разрешите установку из неизвестных источников) и откройте приложение. Оно начнёт слушать и покажет «Ждёт компьютер».
2. **ПК:** установите Python 3.10+ и запустите `windows\run.bat`. При первом запуске создастся виртуальное окружение и поставятся зависимости.
3. Выберите телефон в списке (или введите его IP) и нажмите **Старт**. Готово.

> Телефон и ПК должны быть в одной Wi-Fi сети (не гостевой, без «изоляции клиентов»).
> На Samsung: *Настройки → Батарея → Ограничения фона → приложение → «Без ограничений»*.

## Объёмный звук в играх (PUBG и др.)

Чтобы 3D работал, игра должна отдавать Windows многоканальный звук:
1. *Параметры → Звук → Дополнительные параметры звука* (или `mmsys.cpl`) → устройство вывода → **Свойства → Дополнительно** → формат **24 бита, 48000 Гц**.
2. Там же **Настроить → 7.1 Surround** (или 5.1) → Далее до конца.
3. В игре выберите вывод на это устройство и режим объёмного звука / 7.1, **выключите** Windows Sonic / Dolby Atmos для наушников, иначе звук сведётся в стерео ещё до PhantomCast.
4. В окне PhantomCast включите галочку **«Объёмный звук 3D»**, надевайте наушники на телефоне и нажмите «Старт». В статусе должно быть «· 3D».

Если устройство настроено как стерео, в статусе будет «3D недоступно: устройство стерео».

## Как это работает

```
Windows                                       Android
┌──────────────────────┐   TCP 50510 (JSON)   ┌──────────────────────┐
│ WASAPI loopback      │ ───────────────────▶ │ сервер управления    │
│  → пересэмплинг/микс │ ◀─────────────────── │ статистика раз в 0,5 с│
│  → PCM или Opus 5 мс │                      │                      │
│  → UDP-пакеты        │   UDP 50511 (звук)   │ джиттер-буфер        │
│                      │ ───────────────────▶ │  → AudioTrack (LL)   │
└──────────────────────┘   mDNS _lanaudio._tcp└──────────────────────┘
```

- **Сервер — телефон**, ПК подключается к нему. Так обнаружение устроено просто, а Windows не просит разрешений брандмауэра.
- **Звук идёт по UDP** — один пакет = 2,5 / 5 / 10 мс звука. На Wi-Fi лучше потерять 5 мс, чем остановить поток в ожидании перепосылки (как делает TCP).
- **Управление — TCP**, строки JSON: hello, статистика, ping. Оборвался TCP — сессия закончилась, звук сразу затихает.
- **Джиттер-буфер** держит минимум заполнения за последнюю секунду около небольшой цели, подгоняет скорость воспроизведения до ±0,3 % (на слух не слышно), чтобы гасить разницу кварцев, и выбрасывает устаревший звук после «пачки» от Wi-Fi. При срыве запас растёт на 4 мс, потом плавно уменьшается.

Подробности протокола — в заголовке [`Proto.kt`](android/app/src/main/java/dev/lanaudio/Proto.kt).

### Из чего складывается задержка

| Звено | Примерно |
|---|---|
| Блок WASAPI loopback | 10 мс |
| Пакет (по умолчанию 5 мс) | 5 мс |
| Wi-Fi | 1–5 мс |
| Джиттер-буфер | 2–10 мс |
| Вывод телефона (AudioTrack + HAL + ЦАП) | 10–20 мс |
| **Итого** | **≈ 30–50 мс** |

Bluetooth-наушники на телефоне добавят свои 100–250 мс — это задержка BT-кодека, от приложения она не зависит.

## Сборка из исходников

**Отправитель для Windows** (Python 3.10+):

```powershell
cd windows
py -3 -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python lanaudio_sender.py            # окно программы
.venv\Scripts\python lanaudio_sender.py --list     # список устройств вывода
.venv\Scripts\python lanaudio_sender.py --headless 192.168.1.50 --seconds 10 --codec opus --source tone
```

**Приёмник для Android** (JDK 17, Android SDK 34; Gradle 8.7 не запускается на JDK 25):

```powershell
cd android
.\gradlew.bat assembleDebug          # или build-apk.ps1 (берёт JDK из Android Studio)
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

Стек: Kotlin 1.9, AGP 8.5, minSdk 26 · Python, PySide6, PyAudioWPatch, soxr, PyAV (libopus), zeroconf.

## Если не работает

- **Телефон не находится** — оба устройства в одной сети? Нет «изоляции клиентов»? Введите IP вручную.
- **Треск и срывы** — поставьте пакет 10 мс, поднимите «Минимальный запас» до 10–20 мс; лучше всего Wi-Fi 5 ГГц и ПК по кабелю. Отключите энергосбережение у Wi-Fi адаптера ПК.
- **Обрывы соединения** — уберите приложение из ограничений батареи на телефоне (см. выше).
- **Звук идёт и из колонок ПК** — loopback снимает копию. Направьте звук нужного приложения на неиспользуемое устройство вывода (*Параметры → Звук → Громкость приложений*) и выберите его источником.
- **На ПК тишина** — WASAPI loopback отдаёт данные, только пока что-то играет; телефон при этом показывает «Подключено · тишина».
