# LanAudio — звук с компьютера на телефон по Wi-Fi

🇬🇧 [English](README.md) · Лицензия MIT · APK брать в [Releases](../../releases)

Windows-отправитель захватывает системный звук (WASAPI loopback) и в реальном времени шлёт его
на Android-телефон в локальной сети. Стерео, 48 кГц, задержка — единицы-десятки миллисекунд.

```
android/   приёмник для Android (Kotlin, AudioTrack low-latency + MediaCodec, без AndroidX)
windows/   отправитель для Windows (Python + PySide6, WASAPI loopback через PyAudioWPatch)
```

## Быстрый старт

1. Телефон: установить APK (`android/app/build/outputs/apk/debug/app-debug.apk`), открыть **LanAudio**.
   Приёмник включается сам и висит в уведомлении («Ждёт ПК»).
2. ПК: запустить `windows\run.bat` (первый запуск сам создаст `.venv` и поставит зависимости).
3. В списке «Телефон» появится `LanAudio SM-A556E` — выбрать, нажать **Старт**.
   Если телефон не нашёлся — ввести его IP в поле ниже (порт по умолчанию 50510).

Экран телефона можно гасить: работает foreground-сервис с WakeLock и WifiLock.

## Где сервер — на телефоне

Как и в LanCam, **сервер — телефон**, ПК подключается к нему:

- **Обнаружение.** Телефон объявляет `_lanaudio._tcp` по mDNS, ПК просто показывает список найденных —
  IP вводить не нужно. Обратная схема (ПК-сервер) потребовала бы второго списка уже на телефоне.
- **Брандмауэр Windows молчит.** ПК делает только исходящие соединения (TCP и UDP), входящие порты
  на ПК не открываются, разрешений спрашивать не нужно.
- **Батарея.** Пока ПК не подключён, телефон только слушает порт: AudioTrack, WakeLock и WifiLock
  включаются на время сессии и выключаются сразу после неё.
- **Один источник.** Если подключится другой ПК, он вытеснит предыдущий.

## Транспорт

- **Звук — UDP**, один пакет = 2,5 / 5 / 10 мс звука (по умолчанию 5 мс = 960 байт PCM).
  TCP не подходит: одна потеря на Wi-Fi останавливает поток до перепосылки (десятки–сотни мс),
  а для живого звука лучше потерять 5 мс, чем ждать. UDP-пакет никто не копит и не перепосылает.
- **Управление — TCP**, строки JSON: «hello» с кодеком и размером пакета, ответ с UDP-портом,
  статистика с телефона раз в 0,5 с, пинг с ПК раз в секунду. Оборвался TCP — сессия закончилась,
  звук сразу затихает (нет «зависшего» звука, если ПК пропал).
- Пакет: заголовок 16 байт (`LA`, версия, кодек, id сессии, seq, timestamp) + данные.
  Пакеты чужой сессии/чужого IP отбрасываются. DSCP EF (очередь «голос» на роутерах с WMM).
- **Кодеки:**
  - **без потерь — PCM 16 бит**, 1,5 Мбит/с, для домашнего Wi-Fi это немного;
  - **сжатый — Opus** 128/192/320 кбит/с, режим `lowdelay`, CBR, кадр = размер пакета.
    Кодирует libopus (из PyAV), декодирует системный MediaCodec на телефоне. Opus добавляет ≈2,5 мс.

## Как держится минимальная задержка (телефон)

- `AudioTrack` с `PERFORMANCE_MODE_LOW_LATENCY`, 48 кГц стерео (родная частота — fast-путь микшера),
  буфер AudioTrack = 2 «burst» HAL (на Galaxy A55 это единицы мс). Если HAL жалуется на срывы —
  буфер растёт на 1 burst (как latency tuner в Oboe).
- **Джиттер-буфер — кольцо, мерилом служит минимум заполнения за последнюю секунду.**
  Цель: минимум ≈ «запас» (по умолчанию 2 мс). Выше цели — читаем чуть быстрее (до +0,3 %, на слух
  не слышно), ниже — чуть медленнее. Это же компенсирует разницу кварцев ПК и телефона:
  задержка не уползает со временем.
- **Если очередь растёт — старое выбрасывается:** скачок более чем на 15 мс сверх цели
  (Wi-Fi «заикнулся» и выплюнул пачку) или превышение «потолка» (120 мс по умолчанию)
  обрезается мгновенно.
- **Адаптивность:** срыв (буфер опустел, а поток идёт) поднимает запас на 4 мс; через 5 с без срывов
  запас плавно (0,5 мс/с) возвращается к минимуму. После паузы старт идёт с запасом + измеренный
  джиттер сети (размах задержки прихода пакетов за 3 с).
- Тишина на ПК (WASAPI loopback ничего не отдаёт, пока ничего не играет) срывом не считается.
- Потоки приёма и воспроизведения — `THREAD_PRIORITY_URGENT_AUDIO`.
- WifiLock `HIGH_PERF` + `LOW_LATENCY`: без них Wi-Fi телефона с погашенным экраном засыпает,
  и пакеты приходят пачками раз в 100+ мс.

В настройках приложения: громкость, «Адаптивный буфер» вкл/выкл, «Минимальный запас»
(при выключенной адаптивности — фиксированный буфер), «Потолок буфера». Внизу — живая статистика:
буфер, вывод, джиттер, потери, опоздавшие, срывы, сбросы.

## Из чего складывается задержка

| Звено | Примерно |
|---|---|
| Движок WASAPI (loopback отдаёт звук блоками по 10 мс) | 10 мс |
| Пакет (5 мс по умолчанию) | 5 мс |
| Wi-Fi | 1–5 мс, с пиками |
| Джиттер-буфер телефона | 2–10 мс (адаптивно) |
| Вывод телефона (AudioTrack + HAL + ЦАП) | ≈10–20 мс |
| **Итого** | **≈ 30–50 мс** на хорошем Wi-Fi 5 ГГц |

Окно ПК показывает оценку сквозной задержки по статистике с телефона.

**Bluetooth-наушники** на телефоне добавят свои 100–250 мс — это кодек BT, от приложения
не зависит (в статистике будет «ОБЫЧНЫЙ путь» вместо low-latency).

## Windows

- `run.bat` — GUI: список найденных телефонов (или IP вручную), устройство вывода
  («Системный звук по умолчанию» или конкретное), качество (PCM / Opus), размер пакета,
  индикатор уровня L/R, кнопка «Старт/Стоп», статистика с телефона. При обрыве сам переподключается.
- Если устройство не 48 кГц — пересэмплирование (soxr); 5.1/7.1 сводятся в стерео.
- Звук продолжает идти и из динамиков ПК — loopback снимает копию. Если нужен звук только на телефоне,
  выберите в «Источнике» неиспользуемое устройство вывода и направьте на него звук приложения
  (Параметры → Звук → Громкость приложений).
- Консольные режимы:
  ```
  .venv\Scripts\python lanaudio_sender.py --list
  .venv\Scripts\python lanaudio_sender.py --headless 192.168.100.3 --seconds 10 --codec opus --source tone
  ```
  `--source silence|tone|loopback` — тишина, тихий тон 440 Гц или реальный звук.

## Сборка Android

```
android\build-apk.ps1
```
Gradle 8.7 не запускается на JDK 25, поэтому скрипт берёт JDK из Android Studio (`jbr`).
AGP 8.5.2, Kotlin 1.9.24, compileSdk 34, minSdk 26. Установка: `adb install -r app\build\outputs\apk\debug\app-debug.apk`.

## Если не работает

- Телефон не находится — проверьте, что оба в одной сети (не гостевой Wi-Fi, не «изоляция клиентов»),
  либо введите IP вручную.
- Треск/срывы — поставьте пакет 10 мс или поднимите «Минимальный запас» до 10–20 мс;
  лучше всего работает Wi-Fi 5 ГГц и ПК по кабелю к роутеру.
- Samsung может «усыплять» приложения: Настройки → Батарея → Ограничения фона → LanAudio → «Без ограничений».
